A control existing does not prove that it works.

A passing test suite does not prove security.

A clean scanner does not prove security.

Authentication does not prove authorization.

The UI does not prove backend enforcement.

A mobile client does not prove server-side enforcement.

Obfuscation does not protect privileged secrets.

Store approval does not prove security.

Framework defaults do not prove deployed configuration.

Source code does not prove runtime behavior.

Infrastructure as code does not prove actual cloud state.

A deleted secret does not prove historical exposure was remediated.

A rate limiter is not effective merely because limiter code exists.

A mitigation is not proven merely because the first exploit attempted no longer works.

Never conclude:

> “Nothing was found, therefore the system is secure.”

Conclude only:

> **“These properties were evaluated using these methods, against these attacker positions, across these surfaces; this evidence was obtained; these bypass strategies were attempted; these uncertainties remain; and therefore this level of confidence is justified.”**

The constitution must establish principles including:

## 1. EVIDENCE OVERRULES CLAIMS

Security claims require evidence.

## 2. UNKNOWN IS NOT PASS

Missing evidence must remain visible.

## 3. AUTHORITY MUST BE ENFORCED AT THE AUTHORITATIVE BOUNDARY

Client-side restrictions are not authorization.

## 4. PRIVILEGE MUST BE EXPLICIT, MINIMAL, BOUNDED AND AUDITABLE

Convenience is not a justification for broad authority.

## 5. DENY BY DEFAULT

Absence of a valid authorization decision must not silently permit access.

## 6. THE MOBILE OR WEB CLIENT IS NEVER THE FINAL AUTHORITY

Distributed clients can be modified, replayed, replaced, or automated.

## 7. DISTRIBUTED BINARIES MUST BE TREATED AS OBSERVABLE

No reusable privileged backend secret may be embedded in a client binary.

## 8. OBFUSCATION IS DEFENSE-IN-DEPTH

It does not replace server-side authorization or secret protection.

## 9. THE DEVICE MAY BE HOSTILE

A device may be lost, stolen, shared, rooted, jailbroken, instrumented, automated, or compromised.

## 10. LOCAL DATA IS PART OF THE DATA LIFECYCLE

Files, databases, preferences, caches, backups, screenshots, notifications, logs, crash reports, and temporary files must be governed.

## 11. PLATFORM PERMISSIONS MUST BE MINIMAL AND EXPLAINABLE

No permission exists merely because a template or SDK requested it.

## 12. SECURITY MUST SURVIVE REPLAY, RETRY, CONCURRENCY AND PARTIAL FAILURE

Happy-path correctness is insufficient.

## 13. PUBLIC FUNCTIONALITY MUST BE ANALYZED FOR ABUSE

Public does not mean harmless.

## 14. EXPENSIVE CAPABILITIES REQUIRE ABUSE BUDGETS

Attackers must not obtain unbounded system work cheaply.

## 15. DEPENDENCIES EXPAND THE TRUST BOUNDARY

Libraries, SDKs, vendors, AI providers, and cloud services require review.

## 16. BUILDS AND RELEASES MUST BE TRACEABLE

The distributed artifact must map to reviewed source, dependencies, configuration, and an authorized build.

## 17. SECURITY-SENSITIVE BEHAVIOR MUST BE OBSERVABLE WITHOUT LEAKING SECRETS

Logging must support detection without becoming a privacy or cost vulnerability.

## 18. SECURITY CONTROLS REQUIRE FALSIFICATION ATTEMPTS

A control is not strong merely because it exists.

## 19. DELETION MUST COVER THE COMPLETE DATA LIFECYCLE

Active storage, caches, local copies, backups, indexes, vendors, and devices must be considered.

## 20. PLATFORM APPROVAL IS NOT SECURITY CERTIFICATION

App-store review, cloud certification, framework adoption, or scanner approval is not proof.

## 21. AI AGENTS ARE PRIVILEGED COMPONENTS WHEN THEY CAN ACT

Their tools, permissions, data access, and side effects must be bounded.

## 22. SECURITY PROPERTIES OUTRANK PAYLOAD-SPECIFIC PATCHES

Regression tests must preserve properties, not only previous exploit strings.

## 23. ROOT CAUSES OUTRANK SYMPTOM PATCHES

Fix architecture and trust assumptions, not merely visible payloads.

## 24. REALITY OUTRANKS TAXONOMY

Keep valid risks even when no framework represents them neatly.

Rationale.

Every control must be:

* specific,
* measurable,
* testable,
* adversarial,
* applicable,
* evidence-based,
* non-duplicative,
* technology-independent where possible,
* actionable,
* regression-protectable.

Reject vague controls such as:

> “Use good security.”

> “Follow best practices.”

# PART VIII — EVIDENCE STATES

Classify conclusions as:

## VERIFIED SECURE

Directly demonstrated under meaningful adversarial conditions.

## VERIFIED VULNERABLE

Direct evidence demonstrates failure.

## STRONG EVIDENCE

Multiple corroborating sources support the conclusion.

## PARTIAL EVIDENCE

Some evidence exists, but uncertainty remains.

## UNVERIFIED

The property appears intended but has not been proven.

## CONTRADICTORY EVIDENCE

Available evidence disagrees.

## NOT OBSERVABLE

Available access cannot determine the property.

Unknown is never Pass.

# EVIDENCE HIERARCHY

From strongest to weakest:

1. Direct adversarial verification
2. Direct runtime and configuration evidence
3. Direct implementation evidence
4. Multiple corroborating sources
5. Documentation
6. Human claim
7. AI claim
8. Absence of findings

A scanner reporting zero findings means only:

> **That scanner reported zero findings under that configuration.**

Nothing more.

# PART XVI — SECURITY PROPERTY TESTS

Every important control should define a reusable property.

Prefer:

> **A user can never modify another user’s object.**

over:

> “Payload X is blocked.”

Prefer:

> **A payment cannot produce duplicate charges under retry or concurrency.**

over:

> “The old duplicate-charge payload no longer works.”

Mobile property patterns must include:

> No modified client can perform an operation the actor is not authorized to perform.

> No privileged reusable backend secret exists in the distributed binary.

> Logout revokes usable authentication state and removes local account data according to policy.

> A deep link cannot bypass authentication, authorization, confirmation, or prerequisites.

> Untrusted WebView content cannot invoke privileged native functionality.

> Sensitive data is not exposed through backups, logs, screenshots, notifications, clipboard, or shared storage.

> Switching accounts cannot expose prior-account caches, notifications, files, or offline queues.

> Revoked access cannot remain valid indefinitely through offline behavior.

> Purchase entitlement cannot be forged, replayed, or duplicated by modifying the client.

> Push actions cannot perform unauthorized state changes.

> Mobile requests cannot force more backend work than the defined abuse budget.

> Third-party SDKs cannot access data or capabilities outside their approved purpose without detection.

Tests must target properties.

Not merely prior payloads.
